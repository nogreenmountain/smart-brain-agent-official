# 新注册账号个人 API 准入方案

时间：2026-10-19 15:07（Asia/Shanghai）；关联[任务](../tasks/2026-10-19-personal-api-registration.md)。

## 原因与行为

个人入口沿用发布时26人名单，先于实时账号状态查询拒绝新账号，因此Key列表和配额查询403，页面无法创建。生产定向聚合证实截图账号有效但名单排除；不能靠逐个加人解决后续注册。

正式个人入口改用实时注册账号校验：auth.users 与 public.users 必须同时存在，账号未禁用、未封禁、未删除、非匿名。会话认证/Key hash归属验证仍先执行；Key配额与创建锁、项目权限及管理权限沿用。保留显式名单模式兼容隔离/灰度及旧调用，正式入口不再读取固定名单。健康信息明确准入策略，动态模式不伪称固定人数。

## 实施顺序与验收

1. 使用实际生产scope复现“名单外但有效的新账号”403；负例覆盖不存在、缺profile、disabled、banned、deleted、anonymous和匿名请求。
2. 最小修改scope与personal app；authoritative与deploy并行版本仅同步相应逻辑，禁止旧同步代理覆盖当前异步/长流源码。工作记录读入口须先核对实际路由。
3. 真实隔离PG/HTTP校验新账号Key列表、默认配额、创建、重复/超额拒绝、跨用户隔离、撤销、已有Key使用与队列鉴权；纯测试上游，零生产Key创建及真实模型调用。
4. 查明今日backup失败和Docker储备不足。满足40/20/250/250GiB、备份终态/登记、无维护pending后才准备新叠加镜像。不能降低门槛或重放历史清理/发布。
5. 固定候选SHA/镜像、当前容器配置与Key聚合基线；受控排空后单次替换个人服务，保留旧版本回退，current unit/writer inventory同步；独立核验实际文件、公网匿名401、健康并发8/24/DB3、原Key数据、无关容器代际。
6. 实际用户登录创建/使用须标为用户侧验收；无该证据不得把隔离成功称作生产领取成功。记录并镜像E盘，按本任务文件提交，不夹带旧dirty。

## 自审

移除名单会扩大到所有有效注册账号，符合新号可自助创建的产品目标；不扩大匿名、禁用或跨用户权限。生产不做schema迁移/历史回写/Key重置，不修改Windows relay。配置或镜像回退保留Key数据；实际回退是否执行单独记录。
