- 当前项目名称：`智慧大脑agent`。
- 已核实 Wiki project_id：`dfaefd9a-8e5e-4775-bc18-e3d551c651e4`。

## 3. 每轮开始：确认任务并读取 Wiki

1. 确认本轮目标、最新决定、暂停/取消事项和授权范围。历史“下一步”不自动成为本轮任务。需要接续时读取已有本地 STATE；本地不存在时从 Wiki 获取状态。
2. 首次使用 Company Memory 时读取其技能说明，以实际工具声明为准。项目未知、切换或有歧义时调用 `list_wiki_projects`；权限失败不能改投其他项目。
3. 项目经验影响答案或实施时，在回答或改代码前检索：通用知识用 `search_wiki`，决策用 `get_decision_records`，案例用 `get_examples`，近期变化用 `get_recent_updates`。
4. 新接手优先搜索稳定交接主题，使用 `get_page` 读取完整快照、版本、更新时间和来源；再按需读取相关决定、变更与阻塞证据。结合最近更新和定向搜索排查更新的回滚/取消记录。
5. 默认一次聚焦检索，读取最相关的 2–4 页，证据足够即停止。当前轮已读且无变化的页面可复用；长任务、目标改变、发布或回滚前重新核对相关更新。
6. 检索结果有限或截断不代表全量覆盖；空结果不等于没有历史。水位按项目保存，只有实际覆盖的时间窗口才能标记已检查，不盲目推进 `since`。
7. 仅在任务需要成员方法或会议决定时调用相应工具，读取正文再引用；遵守成员及项目权限，不获取成员原始聊天，不把成员经验自动当公司政策。

信息不足明确标注未知，只暂停依赖该信息的动作，继续无关工作。

## 4. 事实、冲突、时间和状态

### 事实与来源

- 用户决定说明允许或要求做什么；运行证据说明实际发生什么。二者不互相替代，后续取消优先于历史批准。
- 优先参考经过验证、仍在有效期且适用当前版本的页面。`generated` 仅作线索；`verified` 也可能过时或内部矛盾。
- 当前状态须有对应环境、版本和时间的依据。测试通过不能冒充上线，历史截图不能冒充实时健康，保留表/源码/容器不能证明功能仍启用。
- 冲突要写清双方结论、来源、时间及当前采用依据；无法解决就标记待确认，不能默默混合或仅按最近上传时间选赢家。
- 重要 Wiki 引用使用 `[Wiki: 标题 (page_id), v版本, updated 时间]`；成员与会议按插件格式引用。不编造字段、来源或链接。

### 时间与身份

- 时间使用含时区的 ISO 8601，例如 `2026-09-11T10:57:56+08:00`。仅知道日期就保留日期并注明具体时间未知；不补造精度。
- 分开记录操作开始/结束、决定生效、逐项最后验证、快照整理、上传请求时间。`state_as_of` 是汇总截止，不代表所有组件在此时重新验证。
- 每项依据注明：本轮验证 / 沿用历史 / 用户告知 / 推断 / 未知。历史补录必须分开操作日期和本次上传日期。
- 服务端发布时间、updated_at、page_id、version、uploaded_by 以实际返回为准。发布前写“以服务端元数据为准”，缺字段写未知；客户端收到响应时间只能叫 `response_received_at`。
- 执行者、决定者、整理工具、上传身份和下一步负责人分开记录。上传者不是默认执行者或批准者；未指定负责人写“待指定”。

### 状态分四个维度

| 维度 | 可用状态 |
| --- | --- |
| 需求/任务 | 进行中、已完成、阻塞、暂停、取消、待确认 |
| 实现验证 | 设计、源码完成、本地通过、隔离验证、已部署、生产读回、完整验收；不适用须解释 |
| 当前运行 | 候选未上线、线上启用、线上停用、已回滚、不涉及运行、未知 |
| Wiki 同步 | 待上传、结果不明、已发布待读回、读回一致、部分同步、失败 |

四维度分别记录：需求取消、曾生产读回、目前已回滚可同时成立；取消不算成功交付，回滚不等于整体验收。

## 5. 每轮收尾：调用、整理、发布、读回

“每轮”是一次用户请求对应的最终答复。必须在发送最终答复之前完成收尾；进度播报、工具结果不单独触发。AGENTS.md 是执行指令，不是独立后台钩子；中断时可能来不及收尾，下次应依据实际遗留状态补核对，不能虚称上一轮已同步。

### A. 检查变化并实际调用

- 有项目事实、决定/取消、交付范围、验证、阻塞、负责人或接续条件的实质变化：收尾用 `search_wiki` 查重，有相关页再 `get_page` 比较。
- 无实质变化：收尾至少调用一次限量 `get_recent_updates` 核对，不为凑次数创建页面。开工调用不能代替收尾调用。
- 收尾发现新冲突或取消决定，先修正结论与待写内容。
- 普通问答、未采纳建议、猜测、无变化进度、重复经验不发布。里程碑、暂停/取消、未完成与接续条件进入交接；PID、实时日志、重试游标等细节留本地。健康观察必须注明时间。

### B. 写入前检查

写入必须满足：项目与授权明确；有实质增量或为接手必需；事实有证据、决定有来源、未知明确标注；已脱敏、查重。

按第 7 节生成正文，经 `propose_memory(content=正文, ...)` 发布。每轮通常 0–2 篇，实质状态变化须形成含本轮变更的完整快照；引用已有 Wiki 时传真实 `source_page_ids`。

使用实际支持的 `memory_kind`，例如 `decision_record`、`workflow_template`、`checklist`、`retrospective`、`timeline_event`；交接回顾可用 `retrospective`。不发明“当前状态”等 API 枚举，分类和发布成功不等于所有事实已独立验证。

每次提交前保留脱敏正文、唯一 sync_id、内容摘要或 SHA、前驱页/版本、请求时间和授权依据。同一次结果不明的写入继续使用原 sync_id 核对，不能换 ID 重发。

### C. 页面与并发规则

- 快照必须包含完整状态和本轮变化，不能只写“其他保持”“见上轮”。关键未变状态、暂停/取消和未完成范围也要保留。
- 优先安全维护原主题；当前 `propose_memory` 没有显式目标 page_id 或版本条件参数，不能假设同标题更新原页，不能把 `source_page_ids` 当更新目标。
- 无法确认安全更新时，可在确认创建语义后使用带唯一记录 ID 的独立快照，标题为“项目名｜项目交接｜记录ID”，保留稳定标签，明确前驱 page_id/版本及取代范围。读回确认实际页身份；创建语义不明或冲突未解则保留待同步稿。
- 写前读最新版本；发现并发修改就合并，不整页覆盖未读内容。没有条件写入接口时，不宣称具备完整并发保护。
- 默认一篇自足快照。必须拆分时先发布变更记录，再发布引用它的快照，共用 change_id；后一步失败标记部分同步，多页发布不具备事务性。
- 旧页未修改时不能声称已标记失效；新快照明确取代的结论。并发分支必须展示或解决冲突，不能按上传日期草率排序。

### D. 发布成功必须读回

- `propose_memory` 的 `status=published` 表示直接创建或更新正式 Wiki，不是仅提交待审核；其他状态按实际返回报告。
- 用返回 page_id 调用 `get_page`，核对项目、关键正文、来源、版本、取消/未完成边界，并确认实际 `uploaded_by`。不得指定或冒充其他上传者，只报告必要身份标识。
- 保存发布/读回回执：sync_id、请求及响应收到时间、实际服务端时间（缺失则未知）、page_id、version、uploaded_by、读回时间与结果。接手时将页面正文和服务端元数据一起读取。
- 只有内容匹配才标记“读回一致”。发布成功而读回失败标记“已发布待读回”，不重复发布；不为补写自身回执反复更新 Wiki。

### E. 失败与恢复

- 写入超时或结果不明：先搜索唯一 ID 并读回，确定是否已经发布，再决定后续；不得盲目重试。
- 插件缺失、网络异常、缺少 `wiki:propose` 或权限失败：保留待同步稿及原因，如实交付；不绕过插件直写数据库或寻找额外凭据。
- 瞬时只读错误最多有限重试一次；权限错误不循环重试。下次相关任务开始时重新检查待同步项的授权、重复和时效，仍有效才补同步；已取消或被取代的草稿关闭，不补发成现行结论。
- 本地 STATE 记录共享快照 ID/版本及未同步差异；业务完成与同步完成分开报告。多任务协作由当前协调者汇总，避免重复发布。

最终答复末尾用一行说明实际结果：`Wiki：已核对，无新增。` / `Wiki：已同步《标题》vN，读回一致；上传者：实际身份。` / `Wiki：已发布，读回待核验。` / `Wiki：未同步，原因……；待同步稿：路径。`

## 6. 上传前的接手可用性检查

正文须独立回答：当前状态、变化、原因、操作/验证/上传时间、具体经过、证据、缺口、负责人、下一步及恢复方式。

- 第 7 节九部分必须保留；无操作/无变更写“无”，不适用说明原因，未知说明影响及核实方式。禁止发布占位符。
- 正文提供关键脱敏结论与必要证据摘要，再附真实来源。仅有本地路径或 SHA 不算可独立理解；受限证据标注访问范围与真实获取渠道，渠道未知写待提供，不扩大权限。
- 实际操作按顺序写明成功、失败、中断、跳过和回滚；计划单列。历史命令不构成接手人立即重跑的清单。
- 验证分清本地、替身、真实隔离和生产；旧测试保留原日期/版本，不累计冒充本轮测试。每个“已完成”必须有范围与验收依据。
- 任务清单保持稳定 ID 与原范围。只掌握部分就注明覆盖不足，不编造其余事项或整体完成率。
- 不把旧 Wiki 或当前快照当生产生命周期许可；接续前仍须当前授权与实际资格。
