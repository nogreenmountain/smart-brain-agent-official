# 开发状态与发布记录维护流程

本流程把本地代码、任务进度和生产版本关联起来。统一入口为 [CURRENT](../CURRENT.md)，任务记录使用 [接续模板](../templates/task-handoff.md)，发布记录使用 [发布模板](../templates/release.md)。现有 `docs/ops`、`docs/plans` 和 `.artifacts` 继续保留，以链接复用。

## 文件分工

| 文件或目录 | 保存内容 | 维护人 |
|---|---|---|
| `AGENTS.md` | 项目规则和入口；既有历史记录保留 | 项目负责人、集成负责人 |
| `docs/CURRENT.md` | 当前任务索引、部署范围、最后核对时间 | 集成负责人 |
| `docs/tasks/<日期>-<任务>.md` | 任务目标、代码位置、证据、下一步 | 任务负责人 |
| `docs/releases/<发布编号>.md` | 新旧版本、配置与迁移、发布和回退实际结果 | 发布负责人 |
| `.artifacts/<任务或发布编号>/` | 本地可留存证据 | 执行者 |

文档与代码随 Git 保存、审查和共享。未提交的文件只存在于本地；推送前检查敏感内容和变更归属，不能将整个脏工作区一起提交。本流程不自动提交或推送。

## 开始一个任务

1. 读取项目规则、当前入口和相关历史交接，确认本轮目标和授权范围。
2. 从模板创建 `docs/tasks/<日期>-<任务>.md`；填写负责人、目标、验收标准和接口依赖。
3. 记录实际权威源码目录、分支、基线提交及已有未提交修改。此仓库文档位置不能自动推导所有模块的权威源码位置。
4. 代码任务按需要使用独立分支，例如 `codex/<任务>`，多人并行使用独立工作目录。任务相互依赖时先确定接口和集成顺序。
5. 在 CURRENT 登记。未知项明确写“未核对”，并说明如何核对。

任务编号贯穿接续记录、证据目录和发布关联。一项任务可跨多次对话，不为每次聊天另建一个重复任务；任务包含多个独立交付时再拆分。

## 记录阶段和证据

开发阶段可用：未开始、开发中、待验证、已验证、暂停、受阻、已结束。部署范围另填：未部署、本地、隔离、灰度、生产、已回退。已验证必须注明验证的是哪项标准和哪份代码。

- 测试后记录命令、环境、源码提交或文件 hash、退出码、结果和日志位置。
- 源码变化后重新判断旧测试的适用范围，不能把旧日志当成新代码的验证。
- 阶段完成、准备切换工作、遇到中断或有长任务运行时及时写 checkpoint；长任务启动后先记录身份和观察方式。
- 只把摘要写进 CURRENT，详细内容保留在任务和证据里。

## 结束或交接

1. 写清已完成与未完成，以及可执行的下一步；下一步应注明前置条件、目标和成功标准。
2. 记录变更文件、Git 保存情况和所有运行中任务。运行状态不明时写“未知”，不能写“无”。
3. 对运行中任务保留任务编号、进程或 Invocation 身份、最近观察时间、只读观察方式和终态判断；接手先观察原任务。
4. 记录不可重跑动作：已完成迁移、Key 签发、撤销、模型批次、备份启动等；说明如何查询原结果。
5. 更新 CURRENT；结束状态不等于生产已上线。

接续提示可以写：“先读 AGENTS.md 和 docs/CURRENT.md，再读任务编号对应记录；核对源码和运行任务身份后，从下一步继续。”记录用于解释状态，不扩展权限，也不复活到期授权。

## 准备和完成发布

1. 从发布模板创建记录，关联任务和验收证据。先填旧版本、候选版本、影响范围、数据兼容性和回退条件。
2. 固定实际发布包身份；有镜像摘要时记录摘要，离线镜像记录 Image ID、归档 hash 和平台。若候选源码有未提交修改，提交编号之外还要记录实际文件清单和 hash。
3. 填写针对本次现场的发布及回退步骤。历史脚本必须先核对目标和前置条件，不能直接重放。
4. 在已有授权范围内执行，记录每步结果；失败或中断保留真实状态。
5. 核对实际流量入口、权限、业务流程、服务绑定及本次要求的恢复能力，再更新任务和 CURRENT。通过的本地测试不替代生产验收。

计划、实际发布结果、实际回退结果分开填写。回退结果缺失表示尚未执行或未证实，不能称为恢复演练通过。

## 并行维护与安全

- 每个任务负责人写自己的任务文件；集成负责人协调 CURRENT、共同接口及发布顺序。
- 记录关键流程与依赖即可，无需每次发布复制整个平台历史。
- Key、Token、Cookie、密码、私有配置和员工正文不进入普通 Markdown、Git 或公开 Wiki。证据只保存可共享摘要；私有证据写访问受控位置。
- 备份必须注明覆盖范围、生成时间及恢复验证；证据归档不自动成为可恢复备份。
- 稳定经验可按明确请求整理进项目 Wiki；临时任务状态留在仓库记录。
